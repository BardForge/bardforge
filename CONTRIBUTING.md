# Участие в BardForge

Спасибо за помощь в развитии инструментов для звукового сопровождения настольных RPG. Начните с существующих Issues в [BardForge Studio](https://github.com/ShinozakiAichi/BardForge-Studio/issues), чтобы не дублировать работу.

## Предложить изменение

Для ошибки приложите шаги воспроизведения, ожидаемый и фактический результат, версию приложения и сведения о среде без персональных данных. Для новой функции опишите пользовательскую задачу и критерии готовности. Крупные изменения архитектуры, зависимостей или формата данных сначала обсудите в Issue.

Подозрения на уязвимости передавайте по [политике безопасности](SECURITY.md), без публичного размещения деталей эксплуатации.

## Подготовить PR

1. Создайте fork и тематическую ветку от актуальной `dev`.
2. Сделайте одно связное изменение. Соблюдайте правила и команды проверки конкретного репозитория.
3. Проверьте затронутый пользовательский сценарий. Для кода запустите применимые проверки; для документации проверьте ссылки, примеры и фактические утверждения.
4. Откройте PR в `dev`, свяжите его с Issue и заполните шаблон. Укажите, что проверено, что не проверено и какие есть риски.
5. Ответьте на замечания ревью. Решение о слиянии принимает сопровождающий с соответствующими правами.

`main` и выпуски предназначены для готовых проверенных версий. Слияние в `main`, публикация релиза и изменение модели лицензирования требуют подтверждения владельца. Вклад через fork не предоставляет автоматически права Write или членство в организации.

## Качество и границы

- Не меняйте пользовательские названия при переводе интерфейса. Поддерживайте RU/EN для новых пользовательских сообщений.
- Сохраняйте существующие данные; для изменений хранения опишите совместимость, миграцию и восстановление.
- Работоспособность сборки не заменяет проверку звука, интерфейса или интеграции в целевой среде. Экспериментальную Foundry-интеграцию нельзя объявлять готовой без проверки в реальном мире с удалённым игроком.
- Не добавляйте секреты, внутренние спецификации, агентские инструкции, локальные пути, чужое аудио, персональные данные или приватные AI-промпты. Для воспроизведения используйте собственные безопасные тестовые данные с понятными правами.
- Новые зависимости и материалы должны иметь понятное происхождение и совместимые условия использования. Собственный код лицензирован по MIT; сохраняйте уведомления авторов. См. [границы лицензии](LICENSING.md). Этот документ не устанавливает CLA или передачу исключительных прав.

## Метки задач

Тип: `type:feature`, `type:bug`, `type:improvement`, `type:documentation`, `type:research`, `type:security`, `type:maintenance`, `type:refactor`.

Область: `area:core`, `area:desktop`, `area:audio-engine`, `area:mixer`, `area:tracks`, `area:scenes`, `area:presets`, `area:foundry`, `area:network`, `area:ui`, `area:plugins`, `area:ai`, `area:voice`, `area:music`, `area:ci`, `area:docs`.

Приоритет назначают сопровождающие: **P0** — критический инцидент, **P1** — серьёзная блокирующая проблема, **P2** — обычная плановая работа, **P3** — небольшое улучшение. Метка `type:security` не означает, что сведения об уязвимости следует публиковать.
