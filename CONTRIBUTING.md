# Участие в разработке

Рабочая интеграционная ветка — `dev`. В `main` попадают только подтверждённые готовые версии.

1. Проверьте существующие Issues и создайте задачу с критериями приёмки.
2. Создайте от актуального `dev` тематическую ветку: `feature/<issue>-<slug>`, `fix/<issue>-<slug>` или другую подходящую категорию.
3. Делайте небольшие Conventional Commits, например `feat(mixer): add group playback`.
4. Выполните проверки из README, просмотрите staged diff и список публикуемых файлов.
5. Откройте PR в `dev`, приложите результаты и ограничения. Решение о слиянии принимает владелец после CI и ревью.

Не публикуйте внутренние ТЗ, агентские инструкции и конфигурации, промпты, трассировки, логи с пользовательскими данными, исходные пользовательские аудиозаписи, модели, ключи или дампы баз. Общедоступная документация допускается после проверки содержимого. `.gitignore` не удаляет файлы из уже опубликованной истории.

`npm run check:public` проверяет отслеживаемые пути и известные форматы ключей. Это дополнительная проверка, а не замена ручному просмотру diff и полноценной проверке секретов.

Для релиза необходимы отдельное ручное решение владельца и реальные проверки целевого сценария, включая удалённого игрока Foundry. Успешная локальная сборка сама по себе не означает готовность релиза.
